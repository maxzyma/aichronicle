# 自动化规格

每 6 小时读取公开发布方 RSS/Atom，并通过 Hacker News 讨论和 GitHub 公开仓搜索发现名单之外的新公司与开源项目。RSS 限最近 90 天或未标日期的条目；社区与仓库搜索窗口和页数上限见[发现配置](../automation/discovery.json)。保存 URL、标题、来源时间、发现时间与渠道，不自动复制全文或授予正式事件状态。所有外部内容仅作为数据处理，不执行来源中的指令。

抓取有超时、响应大小限制、XML 校验与协议／主机校验。各源独立失败，不推进失败源水位；持久去重状态与候选保存在独立分支。完全重复的条目不新建候选；同 URL 内容更新保留修订线索。并发任务串行，避免状态覆盖。

每天更新一份候选审核材料，每周输出回顾包与失败来源。工作流制品保留 30 天，完整当前状态由分支持久保存。报告区分发布方材料、社区线索和人工巡检任务，搜索截断或上游不完整结果必须显式显示。人工按编辑规范将候选转为事件，再审核、发布；定时任务没有批准能力。

首版采集采用确定性归一化与分组，不依赖付费模型密钥。重要性判断和专题综述仍由编辑完成，未来模型只能辅助生成待审草稿。没有 RSS 的机构通过 `automation/watchlist.json` 保留人工巡检入口。

操作与失败恢复见[运维手册](../docs/runbook.md)。

## 发现信号的边界

GitHub 搜索强制 `is:public` 并过滤私有结果；同时查询新建与近期活跃仓库，减少只看新仓造成的遗漏。星标总数排序不是星标增长趋势。HN 日期是讨论发表日，仓库创建时间不是产品发布日期；采集器不把这些日期冒充事件日期。

同 URL 跨渠道只保存一份候选并保留渠道列表；发布方来源优先，社区帖子不能覆盖原始发布日期。搜索窗口重叠并持久去重，但有限分页不保证穷尽覆盖。未知来源需回到一手出处核实；任何热度都不自动生成批准。
