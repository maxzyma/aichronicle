# AI Chronicle 建设计划

本计划面向维护者与贡献者，回答内容如何积累、站点如何生成、自动化如何持续运行。产品边界见[规格索引](../specs/README.md)，交付状态见[路线图](roadmap.md)。

## 目标与首版范围

面向需要回顾技术来路的 AI 从业者，以一条精选主线和 Agent 专题起步。主线记录改变行业方向的节点，专题保留理解细节；同一事件共享事实，分别说明入选理由。研究范围以[批次截点](../research/reviews/batch.json)为准，不将未核实的近期传闻补成事实。

```text
  collectors/          RSS/Atom 采集与归一化
  pipeline/            审核包、候选报告、人工批准命令
  checks/              数据合同与发布边界检查
  feeds.json           发布方 RSS 来源
  discovery.json       社区与公开仓发现
  watchlist.json       人工巡检来源
  reviewers.json       维护者名单
site/
  src/                 共用布局、组件、页面、样式
  public/              公共静态资源
docs/                  建设计划、路线图、运维手册
templates/             贡献者事件模板
tools/                 文档导航与链接检查
tests/                 内容与采集关键行为测试
.github/workflows/     验证、采集、Pages 发布
```

`sources/` 保存依据，`research/` 保存理解，`content/` 保存结构化记录。事件可以是候选，只有有效人工审核记录使其进入正式站点。网站是派生物，不手改构建产物。

未经允许转载的外部材料只保留书目信息与原创摘要。拥有明确再分发许可的原件以后放入 `sources/originals/`，同时登记许可、获取时间与校验值。每个受治理目录有 README 入口；新增文档必须从根 README 可达。

## Agent 素材接入

以作者提供的手写时间线为研究种子，保留公开整理稿和版本说明。公开稿去除不可公开身份与案例，不复制权利不明的图片；它提供线索，不替代论文、官方公告等一手来源。

逐项区分概念讨论、论文首版、产品预览、正式开放、生态采用和治理变化。“首次”“广泛采用”“替代旧路线”等判断需要额外证据。尚未证实的部分进入[缺口清单](../research/reviews/gaps.md)，不强行生成事件。

## 研究与审核

1. 建立历史骨架和 Agent 线索，记录研究截点。
2. 打开原始出处，核对主体、事实、日期及精度；影响判断单独写明。
3. 通过机器检查生成逐条审核包，编辑预览同时展示候选状态。
4. 人工核实并决定收录、转入专题或剔除，记录与内容绑定的审核指纹。
5. 正式构建只读取通过审核的事件；事实或来源变化后重新审核。

数量不是入选标准。首轮目标是形成可讨论的历史骨架、近期线索与研究缺口，后续按证据补齐地区、组织、治理和科学方向。数据合同见[规格](../specs/data-model.md)。

## 站点与自动化

Astro 静态生成，默认发布到 GitHub Pages 项目地址。主线、Agent 专题、搜索／筛选、事件详情、来源与综述共用组件。自定义域名迁移需同步基路径、DNS 与 Pages 设置，具体步骤见[运维手册](runbook.md)。

每 6 小时采集发布方 RSS/Atom，并检索社区讨论及公开仓库，去重并保留渠道、水位、修订与错误。发现热度只提高核查优先级，不代替入选判断。每日形成近 24 小时候选包，每周形成近 7 天回顾包。持久状态在独立分支，报告在 Actions 制品中；自动化无权批准事件。没有稳定 feed 的机构进入人工巡检列表，不能把 feed 覆盖误认为行业覆盖。

## 验收

- 文档入口完整、相对链接有效、生成审核包与事实源一致。
- 事件日期、引用、唯一性、人工审核指纹与发布边界检查通过。
- 采集重复不新增候选，失败不推进成功水位，修订保留旧值。
- 桌面与手机可阅读、筛选、进入详情与来源，刷新保留筛选条件。
- 正式构建不生成待审事件路由，预览构建不进入 Pages 发布。
- GitHub 验证、定时采集和 Pages 发布实际运行后记录结果；独立域名未配置前明确保留默认地址。
